# Скилл $autopilot — Автономный Оркестратор («Архитектор + Субагенты»)

Когда пользователь вызывает `$autopilot` или передаёт многофазный мастер-план:

## 1. Режим работы (Без лишних остановок)

- Ты выступаешь как **Ведущий Архитектор и Оркестратор**.
- **Не останавливайся и не проси подтверждения между фазами**, если сборка и тесты проходят успешно. Выполняй фазы и финальную проверку автономно за один запуск.
- Останавливайся и спрашивай пользователя перед деплоем в продакшен (`git push` / `ssh sawmill`) или если обнаружено критическое противоречие в бизнес-логике, которое невозможно разрешить самостоятельно. Учитывай ранее выданные пользователем разрешения.
- **Проявляй инженерную инициативу:** самостоятельно устраняй упущенные краевые случаи, включая гонки транзакций, проверку `organization_id`, валидацию отрицательных чисел, `min-width: 0` в UI и отмену устаревших HTTP-ответов.

## 2. Экономия токенов через Subagents (Изоляция контекста)

Разбивай крупную задачу на необходимые изолированные фазы по слоям из `AGENTS.md`:

- **Фаза A (БД и Домен):** только `migrations/*`, `docker-compose.yml`, `internal/domain/*`.
- **Фаза B (Репозиторий):** только `internal/repository/*` и проверка `go build ./internal/repository/...`.
- **Фаза C (Сервисы и HTTP):** только `internal/service/*` и `internal/transport/http/*`, проверка `go build ./...` и `go test ./...`.
- **Фаза D (UI в `web/index.html`):** по правилам скилла `$ui`. Не читай Go-бэкенд, кроме максимум 1–2 файлов хендлеров для сверки JSON-контракта.

Если доступны субагенты, делегируй каждую фазу отдельному узкому субагенту. Передавай точный список разрешённых файлов для чтения и требуй краткий отчёт до 15 строк. Если выполняешь фазу сам, читай только файлы текущей фазы по карте маршрутизации из `AGENTS.md`.

## 3. Автономный цикл контроля качества после каждой фазы

После каждой фазы без участия пользователя:

1. Для Go-кода запускай `go build ./...` и релевантные `go test ./...`. При ошибке исправь её. Для промежуточной фазы с ещё не обновлёнными зависимыми слоями проверяй соответствующий пакет и выполни полную проверку после обновления зависимостей.
2. Для `web/index.html` проверяй синтаксис JS, сохранность `data-a`, `FORMS`, `ACT`, адаптивность на 390 и 1440 px и темы `dark` и `light`.
3. В конце всех фаз кратко обнови `PROJECT.md` и выдай единый итоговый отчёт.
